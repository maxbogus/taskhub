# Collection map — where agents find tasks and notes

> **Purpose.** One reference for TaskHub collection: what the importer scans,
> where an agent should look when the database has no answer, and how the
> registry is kept in line with the folders on disk.
>
> **Rule of thumb for agents**
> 1. Query TaskHub first (`list_tasks`, `project://{slug}/backlog`, `search_notes`).
> 2. Check `docs/PROJECT_AUDIT.md` if a project looks empty — a missing root is
>    reported there, not silently imported.
> 3. Only if something is missing, read the source files listed below.
> 4. Never treat a folder as "no work" until the places in the table are checked.

## Registry health

Generated by TaskHub, never edited by hand:

| File | Content | Regenerate with |
|---|---|---|
| `docs/PROJECT_AUDIT.md` (gitignored) | stale roots, duplicate registrations, uncovered directories, archived projects | `uv run taskhub audit-projects --root ~/Repositories --format markdown --out docs/PROJECT_AUDIT.md` |
| `docs/PROJECT_SYNC.md` | policy A (slug immutable, `root_path` moves) and the 2026-11 migration record | hand-written |

`src/taskhub/sources.yaml` also declares `discovery.exclude`: published
snapshots (`workshops/idea-to-spec-*/framework`) and archive copies
(`conf/archive/*`) must never become projects.

## What TaskHub scans automatically

Which files are collected is declared in `src/taskhub/sources.yaml` (not in
code). Override the whole file with `TASKHUB_SOURCES_FILE`.

Tasks (`services/backlog_importer.py`):

| Source | Pattern |
|---|---|
| Task folders | `ai/tasks/**`, `ai/backlog/**`, `docs/backlog/**`, `docs/tasks/**`, `backlog/**`, `tasks/**` |
| Analysis / roadmaps | `ai/analysis/**/*.md` (roadmap, RICE, task matrix) |
| Root backlogs | `BACKLOG.md`, `backlog.md`, `docs/TASKS.md`, `TASKS.md` |
| Project README | `README.md` / `readme.md` **only when it has a Roadmap/TODO/Backlog/Plan section** |

Notes and ledgers (`services/note_importer.py`):

| Source | Pattern |
|---|---|
| Ledgers | `docs/ledger/*.jsonl` (decisions, findings, submissions, benchmarks) |
| Handoff | `docs/HANDOFF.md`, `HANDOFF.md` |
| Notes | `docs/notes/*.md` |
| Sessions | `docs/sessions/*.md`, `reports/sessions/*.md` |
| Ledger rules | `.clinerules/*-ledger*.md` (`meta.ledger_type=rule`) |
| Global memory | `~/.cline/memory/*.jsonl` → pseudo-project `memory` |
| Portfolio root | `INDEX.md`, `STATUS.md`, `SUMMARY.md` → pseudo-project `portfolio` |

## Portfolio layout

The repositories root is a flat set of projects plus a few containers:
`career/`, `hackathons/`, `legal/`, `work_projects/`, `study/`, `landings/`,
`infra/`, `conf/`, `archive/`, `workshops/`. A folder inside a container is a
project on its own, even without a marker file — those names are listed in
`CONTAINER_DIRS` in `services/projects.py`.

The authoritative project list is the database, not a markdown file:
`list_projects`, `project://{slug}/backlog` and the generated
`docs/PROJECT_AUDIT.md`. Do not hardcode a project list here: it drifts, which
is exactly what M16 fixed.

## When the database has no answer

1. `uv run taskhub audit-projects --root ~/Repositories` — is the project stale,
   detached or simply empty?
2. `uv run taskhub sync-projects --root ~/Repositories --max-depth 3 --dry-run`
   — would a newly created folder be registered?
3. Read the source places from the tables above; a folder with no markers and no
   sources listed there is genuinely empty (report it, do not invent a backlog).

## Commands

```bash
# register newly found projects (dry run first: it lists every decision)
uv run taskhub sync-projects --root ~/Repositories --max-depth 3 --dry-run
uv run taskhub sync-projects --root ~/Repositories --max-depth 3

# move a project after a folder rename (slug and work items are kept)
uv run taskhub move-project --slug <slug> --root <new path>

# soft archive / restore (refuses to hide a project that still has work items)
uv run taskhub archive-project --slug <slug> [--force] [--restore]

# import tasks and notes
uv run taskhub import-all --dry-run
uv run taskhub import-all --notes
uv run taskhub import-notes --no-memory        # project ledgers only

# export a digest for writing posts
uv run taskhub export --project <slug> --format markdown --out posts/<slug>.md
```

## Relationship to the `.clinerules` ledgers

`.clinerules/*-ledger*.md` describe **how** to write `docs/ledger/*.jsonl`.
TaskHub imports both: the rules as `kind=ledger, meta.ledger_type=rule`, and
the ledger entries themselves as `decision` / `insight` / `ledger` notes linked
to tasks by `tickets` ids.

Idempotency key: `note.external_ref = "<relative path>:<entry key>"`, unique per
project. Re-running an import updates or skips, never duplicates.
